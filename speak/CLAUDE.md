# speak

A tiny front-end for MLX audio text-to-speech. Type in the big text box, pick a model, voice and language, and press the big button (`⌘↩`). The first press generates the speech in the background, with a progress bar, and plays it as soon as it's done. After that the button says Play and replays the cached file. Changing the text, model, voice or language makes the button say Generate again, and the next generation replaces the cached file. Save (`⌘S`) copies the cached file to `~/Downloads/<noun>_NNN.wav`, where `<noun>` is the first proper noun of the text in lower case and `NNN` is the lowest free index. A model that isn't downloaded yet turns the button into "Download <size>", with the same progress bar and a Cancel option. Voice and language are independent: a mismatch is allowed and just noted in the hint line.

**Files:** a `.txt` or `.md` file can be opened with `⌘O`, the File button, drag and drop, or `speak <file>`. Its text is cleaned up for speech and shown in the box (`sp_plain`: Markdown syntax, code blocks and front matter go, hard-wrapped lines are rejoined, and typographic punctuation becomes ASCII for the font). While a file is open, Save writes next to it as `<file name>_NNN.wav`, ignoring `SPEAK_SAVE_DIR`. Clearing the text box goes back to typing mode.

## Commands

Built from the repo root (see `../CLAUDE.md`): `cmake --build build --target speak`, run `./build/bin/speak` (launcher `speak`), test the core with `./build/bin/speak_tests`.

- **Scripted UI runs:** `SPEAK_DRIVE=<script>` replays clicks, typing and keys through the real event path at the widgets' computed positions, with the real worker. It saves frames with `shot`, and exits 2 on any `FAIL` (including the app quitting early). Scripts live in `tests/drive_*.txt`; see the comment above `drive_step` in `main.c` for the commands. Run them from a scratch dir with `SPEAK_SAVE_DIR=$PWD` so saves stay out of `~/Downloads`. For `drive_file.txt`, first copy `tests/chapter.md` into the scratch dir (saves land next to it). For `drive_download.txt`, add `HF_HUB_CACHE=$(mktemp -d)` so the download starts from an empty cache. Scripted runs keep prefs in their temp dir.
- **Other environment variables:** `SPEAK_PYTHON` overrides the interpreter (the default is resolved at configure time, the real `sys.executable` behind any pyenv shim, cached as `SPEAK_PYTHON`). `SPEAK_WORKER` overrides the worker script. `SPEAK_TEXT` prefills the text box (useful with `TINY_SCREENSHOT`, which skips starting the worker).

## Architecture

- **`src/speak.{c,h}` is SDL-free** (built as `speakcore`). It does word wrapping over UTF-8 (one font cell per code point), the save prefix (`sp_prefix`: a capitalized word that doesn't start a sentence, then a sentence-initial one that isn't a function word, then any non-stopword, else `speech`), next-free save paths, and protocol escaping and splitting.
- **`worker/speak_worker.py` does all the speech work.** `serve` is a persistent child process that keeps the last model loaded, so later generations skip the ~2 s load. It reads tab-separated commands on stdin and writes replies on stdout, and its docstring documents the protocol. mlx-audio's own prints are redirected to stderr, which the app passes through to the terminal. A newer `gen` cancels one in flight, checked between stages. Text up to the model's `MAX_CHARS` (Kokoro 400, from its 510-phoneme chunk limit; Qwen3 1200, from its 2048-codec-token cap) is a single `generate` call. Longer text is generated in stages: it's split at paragraphs and packed up to that limit (an overlong paragraph splits at sentences), the status shows "Part i of n", and all stages go into one file. Progress within a stage follows the audio produced. `download <repo>` is a separate one-shot process, so downloading doesn't block generation. It uses the same allow patterns as `mlx_audio.utils`, and reports progress as blob bytes over the repo size (monotonic).
- **Models:** a curated list (Kokoro, plus Qwen3-TTS CustomVoice) and any other cached model of those families. "Local" means the snapshot has `config.json` and weights, and no `.incomplete` blob is still in flight. A cancelled download can leave a stale `.incomplete` next to its finished blob, which is ignored. Voices come from Kokoro's `voices/` folder or Qwen's `talker_config.spk_id`. Languages are Kokoro's single-letter codes or Qwen's language names.
- **Without espeak-ng** (`brew install espeak-ng`), Kokoro can only do English, and it can't pronounce out-of-vocabulary words. The worker installs a misaki fallback that drops those words and reports them (`note` → "skipped Eiffel (needs espeak-ng)"). Other languages fail with a plain message naming the fix. Chinese and Japanese need misaki's extras instead (`pip install "misaki[zh]"`, `"misaki[ja]"`), and their ImportError is reworded the same way.
- **Async plumbing in `main.c`:** SDL3's process pipes are non-blocking, so each child gets a reader thread. The thread polls stdout, queues whole lines, and pushes a registered user event, which keeps the main loop event-driven. Replies carry the job id, and stale ones are ignored. If the worker dies, it's restarted on the next request.
- **Cache:** one temp WAV in `$TMPDIR/speak-<pid>/`, keyed by model, voice, language and text (`request_key`). It's replaced when a new generation finishes and removed on quit. Playback is an SDL audio stream, and the bar follows its queued bytes (a 33 ms wake-up while playing).
- **Prefs** (last model, voice, language) live in `SDL_GetPrefPath("tinyapps", "speak")/prefs.txt`.
